     Jain AI (ai.jaingenius.org) — Implementation Plan

     Context

     E:\Downloads\Chickpete\ai.jaingenius.org contains only PRD.md (no git, no
     package files). Tooling present: Node 24.16, npm 11.13, git 2.41. The PRD
     calls for a new, independent Astro + TypeScript static site, which launches
     as a content-first resource hub (Phase 1) with no DB, auth or AI APIs, and
     grows through later phases. The PRD says to work one milestone per
     session, state files and acceptance criteria at the start of each one, and
     run type-check, lint and build after every change.

     Defaults assumed (change any before approval):
     - Build in this folder (ai.jaingenius.org) instead of making a new
       ai-jaingenius folder. The PRD allows "or equivalent". git init here.
     - Styling: plain CSS custom properties (design tokens), no Tailwind.
     - Hosting: Cloudflare Workers Static Assets with a static Astro build
       (output: 'static', no adapter until Phase 4). Deploy with wrangler deploy
       using a wrangler.jsonc that sets assets.directory = ./dist and
       not_found_handling = "404-page".
     - Content is MDX/Markdown plus a few JSON collections, using Astro Content
       Layer (src/content.config.ts, glob() loader, Zod schemas).
     - Initial content is a small seed set of real examples. Anything religious
       (dates, significance) gets religiousReviewStatus: "pending" and a visible
       "Pending review" label. Asset licences are never invented: asset records
       are only added with a known source and licence.

     ---

     Phase 0 — Foundation (1 session)

     M0.1 Scaffold
     - npm create astro@latest (minimal, TS strict) → astro.config.mjs with
       site: 'https://ai.jaingenius.org', @astrojs/mdx, @astrojs/sitemap.
     - Dev deps: prettier, prettier-plugin-astro, eslint + eslint-plugin-astro +
       typescript-eslint, @astrojs/check, wrangler.
     - Scripts: dev, build (astro check && astro build && pagefind is added in
       Phase 1), preview, check, lint, format, deploy.
     - .gitignore (node_modules, dist, .env*, .wrangler), .env.example
       (placeholders only), README.md, CLAUDE.md (guardrails taken from PRD
       §16).

     M0.2 Design system and shell
     - src/styles/tokens.css (maroon / cream / saffron / gold / charcoal, type
       scale, spacing, focus ring) and global.css.
     - src/layouts/BaseLayout.astro, which handles title, description,
       canonical, OG/Twitter meta, and a skip link.
     - src/components/: Header.astro (Explore / Learn / About, plus a search
       entry), MobileNav.astro (works with <details> and no JS), Footer.astro,
       SEO.astro.
     - src/pages/index.astro (placeholder intro, no dead links),
       src/pages/404.astro, public/favicon.svg, public/robots.txt.

     M0.3 Deploy config
     - wrangler.jsonc for static assets, plus README steps for npx wrangler 
       login and npm run deploy and for adding the custom domain
       ai.jaingenius.org.

     Phase 0 acceptance: clean npm ci && npm run dev works, npm run build
     passes, there are no absolute paths or secrets, and git init is done with a
     first commit.

     ---

     Phase 1 — Public Resource Hub (MVP, ~8 sessions)

     M1.1 Content schemas and data layer
     - src/content.config.ts defines collections prompts, templates, assets,
       tools, festivals, guides, with fields exactly as in PRD §7.1 and status: 
       draft|published|archived.
     - src/lib/content.ts is a small read API (getPublished(type), getBySlug,
       getRelated) that filters status === 'published'. Pages use only this API,
       so D1 can replace it in Phase 2.
     - src/lib/format.ts covers dates, file sizes and licence labels. Vitest
       unit tests go in tests/unit/.

     M1.2 Shared UI components
     - ResourceCard.astro, Tag.astro, Badge.astro (Prompt / Template / Download
       / External tool / Pending review), EmptyState.astro, Breadcrumbs.astro,
       CopyButton (small vanilla <script> that falls back to selectable text; no
       React unless needed), FilterBar.
     - Filtering uses static category pages (/prompts/category/[cat]), so it
       works without JS. A light client-side tag filter adds to it.

     M1.3 Prompt Library: /prompts, /prompts/[slug] with copy, metadata and
     related prompts. Seed ~10 prompts.
     M1.4 Templates and Assets: /templates, /templates/[slug], /assets,
     /assets/[slug]. Format, size, licence and attribution appear before the
     download button. Preview images go through astro:assets (WebP/AVIF,
     explicit dimensions, lazy loading).
     M1.5 AI Tools Directory: /tools, /tools/[slug], showing freePlanStatus, the
     caveat, "Last verified" and the official link (rel="noopener noreferrer").
     Seed ~8 tools (ChatGPT, Gemini, Claude, Canva, Ideogram, etc.) with
     today's verification date.
     M1.6 Festivals and Learning Centre: /festivals, /festivals/[slug] (date
     description, sources, last verified, related prompts and templates),
     /learn, /learn/[slug]. Seed festivals: Mahavir Janma Kalyanak, Paryushan,
     Das Lakshan, Diwali (Nirvan), Akshaya Tritiya, Samvatsari, all marked
     pending review.
     M1.7 Search: Pagefind runs after the build (data-pagefind-body on detail
     pages, data-pagefind-filter for type and category). /search page plus
     header search. A <noscript> fallback links to category indexes. Includes a
     no-results state.
     M1.8 Static pages, homepage and SEO polish
     - /about, /guidelines (PRD §7.2), /privacy, /terms, with a takedown/contact
       email.
     - Homepage gets the hero and tagline, search, featured categories, and
       recently added items.
     - Sitemap, canonical URLs, OG on every detail page, and a broken-link check
       (astro build combined with a link-check script).

     M1.9 QA gate
     - Playwright journeys in tests/e2e/: Journeys A, B and D from the PRD,
       search, 404, mobile viewport, and JS disabled for reading.
     - @axe-core/playwright accessibility checks and a Lighthouse run on core
       pages (target 90+).
     - Religious content and asset permission review checklist recorded in
       README.

     Phase 1 acceptance: the PRD §5 Phase 1 criteria and §15 release gates.

     ---

     Later phases (planned only after Phase 1 ships; each gets its own detailed 
     plan)

     - Phase 2, CMS: add @astrojs/cloudflare adapter, D1 (migrations/), R2
       uploads, Cloudflare Access on /admin/* and /api/admin/* with JWT verified
       server-side, admin/editor roles, audit log, import/export. Swap the
       src/lib/content.ts implementation to read from D1.
     - Phase 3, Builders: /studio/* React islands (Festival Kit, Prompt,
       Invitation, Caption, Poster Brief). Deterministic template assembly from
       reviewed JSON templates, with copy / download .md / reset and clear
       "assembled text, not AI" labels.
     - Phase 4, Text AI: /api/ai/* Workers behind a generateText / estimateUsage
       / getProviderStatus adapter, secrets via wrangler secret, Turnstile,
       D1-backed quotas and rate limits, and a "draft" label on output.
     - Phase 5, Images: only after cost caps are proven. Phase 6 is optional.

     Verification (each milestone)

     npm run check && npm run lint && npm run build && npm run test (Vitest,
     later Playwright), then npm run preview and a manual click-through on
     mobile and desktop widths. Report files changed, results, limitations and
     the next milestone.

     Next step after approval

     Execute Phase 0 only (M0.1–M0.3), then stop for review.
